# 每轮工作单模板

把一轮 Logo 工作派给执行者时使用。按轮次删掉不适用的段落；工作单放在仓库外，执行者在独立分支或 worktree 里工作。

```markdown
# 工作单：<产品> Logo 第 <n> 轮（<本轮主题>）

先读 <Issue 链接> 和仓库的 AGENTS.md。只改 `<品牌目录>/`。

## 背景

- 产品：<名字的来历、一句话定位、目标平台>
- 所有者已有产品的 Logo：<造型与主色>。新方向避开它们。
- 情绪板：<仓库外路径>。只吸收风格，不照搬其中任何现有 Logo。
- 已知撞脸风险：<知名同类标志>。

## 上一轮反馈（第 2 轮起）

- 原话：<所有者的话>
- 指挥核对出的具体问题：<定位到路径段或形体交接处，例如“头部侧面是 L 28 19 → 28 46 的竖直线”>

## 要求

- R01：先调研商店真实图标并归纳，再出 3–4 个方向，每个一句话说明表达什么。
- 精修轮：只改反馈范围；出 A1（只改问题一）/ A2（只改问题二）/ A3（合并），附叠图和交接处局部放大；保留已认可的部分：<列出>。
- 可编辑源 SVG，部件独立路径并命名；曲线相切，关键轮廓 G2；负形缝隙宽度统一；圆角取值成体系并写进 README。
- 检查尺寸：1024 / 128 / 32 / 16，<平台特殊尺寸>；主色版和单色版。
- 竞品截图和参考图不进公开仓库；临时文件放工作单目录的 scratch/，完成后删除。

## 交付

- 产出放 `<品牌目录>/rounds/R<nn>-<日期>/`，含 index.html 汇总和 README（记录上一轮反馈）。
- 推到 <PR>，不合并。
- 工作单目录写 REPORT-R<nn>.md（30 行以内）：各方向一句话、最推荐哪个及理由、哪些检查是脚本做的、哪些是人工看过的。
- 完成后终端最后一行单独输出 `<完成标记>`。
```

## 定稿轮的差异

定稿轮不做造型探索。工作单要写明：母版文件和画板、“不要改动任何路径”、已确认的规范数值、导出物清单、清单与 `--check` 要求，以及 FINAL 记录的位置。
